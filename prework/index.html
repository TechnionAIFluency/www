Prerequisite

Four things, before Week 1

None of this is taught in the course and none of it is graded on its own. It is what Week 1 assumes you already have, so that the first session can start on the subject instead of on installation.

What to arrive with, and why each is needed.
What Why
Python you can read Week 1 reads agent-written Python and reviews a diff. Writing it from scratch is not asked for; following it is.
A real Unix shell Every exercise session runs commands. On macOS and Linux you already have one. On Windows, WSL2 — the Windows Subsystem for Linux — is the course's shell.
uv One command installs Python, builds the course environment and pins every package. Install uv itself here; the environment is built in the Week 1 exercise session.
A GitHub account with two-factor authentication All work is delivered as pull requests. Registering the account with course staff is part of milestone P1, due Week 2.

First

Learning Python

Cover the fundamentals first — syntax, variables, data types, operators, conditionals, exceptions, functions, loops — before anything that looks more interesting. The advanced half (comprehensions, generators, regular expressions, type hints, decorators, object-oriented programming, recursion) can wait, and style can wait longer.

A few places to learn it. Free, and in rough reading order.
Resource What it is for
Python course in Hebrew, CAMPUS A free self-paced beginner course, in Hebrew. The fastest route in for most students here.
The official Python tutorial The canonical reference for the fundamentals, written by the people who made the language. Short, and it never goes out of date.
Learn Python — Full Course for Beginners Four hours, free, covers the whole of the fundamentals list above in one sitting.
Software Carpentry lessons The Unix shell, git and Python, taught for scientists. It covers the second and third things on this page as well as the first.
NumPy: the absolute basics Arrays are how numbers move around an engineering project. Read this once you are comfortable with lists and loops.
PEP 8, the style guide Last, not first. Worth reading when you can already write the code it is about.

These are drawn from the research group's own Python page, which carries the longer list, including the advanced material and the repositories to practise on.

Second

A Unix shell: WSL2 on Windows

On macOS and Linux you already have a shell and there is nothing to do here. On Windows, install WSL2 — the Windows Subsystem for Linux. It is a real Linux running alongside Windows, not an emulator, and it is where every command in this course is typed.

Installing WSL2. Seven steps, about twenty minutes, most of it the restart.
Step Do this What it does
1. Check the Windows version Windows 11, or Windows 10 build 19041 and later winver in the Start menu says which you have. Older builds need the manual install route in Microsoft's own documentation.
2. Open PowerShell as administrator Start menu, right-click Windows PowerShell, then Run as administrator The install writes system features, so an ordinary prompt fails here.
3. Install wsl --install One command. It enables the two Windows features, installs WSL2 and installs Ubuntu.
4. Restart Windows Reboot when asked The features are not active until the restart. Skipping it is the most common reason the next step appears to hang.
5. Create your Linux user A username and a password, at the first Ubuntu prompt This is a Linux account, unrelated to your Windows login. The password is invisible as you type it; that is normal, not a frozen terminal. Remember it — sudo asks for it.
6. Confirm you are on version 2 wsl -l -v The VERSION column must read 2. If it reads 1, run wsl --set-version Ubuntu 2.
7. Update the distribution sudo apt update && sudo apt upgrade First thing in a fresh Ubuntu, and the first real use of the password from step 5.

Three things that catch people:

  • Install fails with a virtualization error. Virtualization is switched off in the machine's firmware. Reboot into BIOS/UEFI and enable Intel VT-x or AMD-V.
  • Keep your work in the Linux home directory, ~, not under /mnt/c. Files on the Windows drive are reachable from Linux through /mnt/c, and everything that touches them — git, package installs, test runs — is several times slower.
  • Use Windows Terminal rather than the standalone Ubuntu window. It ships with Windows 11 and is a free install on Windows 10, and it is what the lecturer will be typing in.

Third

uv, which installs everything else

uv is the only Python tool this course asks you to install. It downloads Python itself, builds the course environment and pins every package to an exact version — one command, uv sync, does all three. Install uv here; the environment is built in the Week 1 exercise session, with teaching assistants in the room.

Installing uv. Four steps, one of which is doing nothing.
Step Do this What it does
1. Install it curl -LsSf https://astral.sh/uv/install.sh | sh Run it inside WSL on Windows, or in Terminal on macOS and Linux. One file lands in ~/.local/bin; nothing is installed system-wide and no administrator password is asked for.
2. Open a new shell Close the terminal and open it again, or source ~/.bashrc The installer adds ~/.local/bin to your PATH, and the shell you ran it in does not see that change. uv: command not found immediately after a successful install is this, every time.
3. Check it uv --version A version number means you are finished. This is the whole install.
4. Do not install Python Nothing to do — this is the step you skip uv downloads and manages its own Python. Installing one yourself, or reusing an anaconda from another course, is the one way to end up with an environment nobody else in the room has.
  • Why a lockfile matters here. The course environment is described by pyproject.toml and pinned by uv.lock, which records the exact version and the hash of every package. That is not bookkeeping: this course is about a model reasoning over a ground that computes the same answer every time, and an environment that resolves differently on your machine and the lecturer's is not that ground. Measured on this course's own reference project, the combustion result is identical to the last bit across two builds of the same library version, and differs in the 11th digit across two others.
  • You will not activate anything. Where other courses tell you to activate an environment before working, here you prefix the command: uv run pytest. There is no state to forget, which removes the most common reason that something that worked yesterday does not work today.
  • About that curl ... | sh. It runs whatever the server sends, so it is worth knowing when that is acceptable. Once, on your own laptop, from the vendor's documented address, with you watching: fine. Unattended inside a container build that an agent then runs in: not fine, and the course's own container image deliberately does it differently. Containment is Week 4. If you would rather avoid the pipe entirely, brew install uv on macOS and pip install uv anywhere both work.
  • Node is not needed yet. From Week 8 some MCP servers run through npx, which needs Node. uv does not manage Node, so it is a separate install — and it is done in the Week 8 session, not now.

Fourth

A GitHub account, with two-factor authentication

Every deliverable in this course arrives as a pull request, so the account is the first thing to exist. Registering it with the course staff is part of milestone P1, due in Week 2.

Creating the account and securing it.
Step Do this Why
1. Create the account Sign up at github.com/signup Use an email address you will still have after graduation. The username appears on every pull request you open, including the ones in this course — choose one you are happy to show an employer.
2. Verify the email Click the link GitHub sends An unverified account cannot be added to the course organisation.
3. Install an authenticator app Google Authenticator, Microsoft Authenticator, Authy, or the one in your password manager A six-digit code app on your phone. Prefer this over SMS: text messages are the weakest second factor and GitHub says so itself.
4. Turn on two-factor authentication Settings → Password and authentication → Two-factor authentication → Enable Scan the QR code with the app, then type the six digits back. GitHub requires 2FA of everyone who contributes code, so this is not optional.
5. Save the recovery codes Download them and keep them somewhere that is not your phone They are the only way back in if the phone is lost. Nobody on the course staff can restore an account for you.
6. Authenticate git itself gh auth login, or add an SSH key Once 2FA is on, your password no longer works for git push over HTTPS. The GitHub CLI does the whole exchange for you and is the route the course uses.

Keep the recovery codes. A lost phone with no recovery codes means a locked account, and the work for this course lives behind it. Save them before you need them.
