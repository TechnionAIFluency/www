Exercises

One exercise session a week

Each session is two hours and is where project work happens: a ten-minute standup, a hundred minutes on your own project, ten minutes to commit and disclose — the weekly rhythm has the minutes. Weeks 11 and 12 apply no new capability; by then you are closing one out. Each week links to its deck once that deck is published. Published decks are shown, with their handouts and files, on the Tutorials page.

A milestone week (M1–M6) has what falls due in a shaded box, as on the Schedule, and a filled square on the rail. Only weeks with published slides have a Materials line.

  1. W01 Environment and git

    • Environment installation: WSL, and the harnesses
    • git intro: branches, staging, commit — the basics

    Materials Slides · Student handout · Activity files:
    setup_treasure.sh · setup_git_quest.sh · project-proposal.md

  2. W02 git, GitHub, and the Setup Gate

    • git: worktrees, merge conflicts
    • GitHub: clone, pull, push
    • Context-window management: handoff, compact/clear, reload, the context indicator
    • Harness intro: OpenCode, Antigravity, Claude Code, Codex
    • TA demo: check-sandbox.sh walked through live — what each check means, and what it cannot prove
    • Setup Gate: run it yourself, then answer why each check exists

    M1 due this week. Problem statement; GitHub user registered with course staff; first merged PR

  3. W03 Wire the harness

    • The harness on your repo: run the loop end to end
    • Skills and hooks: write one of each
    • Adversarial development: demo and practice
    • First agent-authored commit: review a diff you did not write

  4. W04 Build the wall

    • Sandboxing in practice: install the wall
    • Canary probe and control: prove it actually refuses
    • Agent env files: write yours
    • Induced injection: plant a hostile file, watch it get read

    M2 due this week. First agent-authored commit

  5. W05 Your domain context pack

    • AGENTS.md: write yours
    • Domain glossaries: practice
    • One skill file: write it and test it
    • Retrieval bake-off: grep against embeddings, on your own corpus

  6. W06 Be grilled

    • Be grilled, smartly: let the agent interview you for 45 minutes — and do not let it write yet
    • Write docs/spec.md: goal, non-goals, anti-goals, boundary, success criteria
    • Qualify your ground against the six criteria: a table, an honest verdict per row
    • Pivot clinic: a ground failing criterion 4 or 6 gets a narrow, TA-approved pivot today

    M3 due this week. Agent environment file (AGENTS.md); domain glossary (GLOSSARY.md); one written skill; written specification (docs/spec.md). Last chance to consider a project revision

  7. W07 Spec → failing tests → green

    • Unit tests, functional tests, evals: demo and practice
    • Spec-derived tests: write them from docs/spec.md
    • Tests and CI: green on GitHub Actions
    • Break it on purpose: find a test that still passes when the mechanism it names is deleted

  8. W08 Your MCP server

    • Write your MCP server
    • The agent calls your ground, end to end
    • Wrap a solver: API against MCP, measured
    • Hallucinated dependency drill: verify every package the agent proposes before installing it

    M4 due this week. One real engineering tool connected and in use; specification-derived tests green in CI

  9. W09 Stand somewhere

    • Declare your intervention points, and commit them
    • Add JSONL logging to your loop
    • Induce a failure, then diagnose it from the log alone
    • Cost run: measure tokens and spend for one full loop

  10. W10 Build your eval, and open the red-team swap

    • Build your eval suite
    • First eval run, scored
    • Calibrate: a reliability diagram on your own predictions
    • Sanity-check harness: units and magnitude assertions
    • Red-team swap: one assigned peer, findings filed as issues — opens here, closes in week 12

    M5 due this week. Declared intervention points; structured logging; one induced failure diagnosed from the log alone; first evaluation run

    • Reserved for project build and the red-team exchange

  12. W12 Open: project build, and the red-team exchange

    • Reserved for project build and the red-team exchange

    M6 due this week. Evaluation suite; red-team exchange closed with a peer; canonical run; demo; tagged release; defence pack

  13. W13 Defence audit

    • Defence audit: answer for your own artifacts
    • Peer demo review
