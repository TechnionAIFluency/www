Topics

What each lecture covers

Topics as placed in the course-flow workbook. Week 12 is open by design: a December decision picks its topic, never its format.

W01 Postures

  • The 10× engineer
  • What is an agent?
  • The three postures
  • The for-loop test: delete the LLM, does a grid search do as well?
  • Where the line falls: what the LLM reasons about, against what the ground computes
  • The environment: WSL, the harnesses, anaconda, git, the Linux terminal
  • git concepts
  • The syllabus, and the final project

W02 LLM science

  • Neural networks; what an LLM is
  • The transformer; next-token prediction
  • The context window
  • Scaling; emergence
  • Per mechanic, what it implies about how the thing fails

W03 The harness

Opens with the Success and Failure gallery for P1 — Repo forked, Setup Gate passed, proposal-draft.md: the problem, the candidate ground, a first guess at the line — which fell due the week before.

  • The harness: the loop, tools, memory — agent = harness + LLM
  • Skills and hooks
  • Model selection and cost as a harness-level decision
  • AI Fluency, and the 4 Ds: Delegation, Description, Discernment, Diligence
  • Automation bias and deskilling — what Diligence guards against
  • The LLM council
  • Adversarial development
  • Subagents, and context isolation

W04 Containment

  • Prompt injection — the motivating attack
  • Untrusted tool output: it arrives in a file the agent read
  • Containment: the two walls
  • Policy against enforcement
  • Fail-open defaults — “enabled: true” proves nothing
  • The canary probe, and why it needs a control
  • Sandboxing; agent env files

W05 Context

Opens with the Success and Failure gallery for P2 — Harness running on your repo, wall proven to refuse, first agent-authored commit — which fell due the week before.

  • Context engineering: what goes in the window, and why
  • Memory, against the context window
  • AGENTS.md and agent env files as a versioned artifact
  • Domain glossaries
  • Retrieval, cheap first: grep → stuffing → BM25
  • Routers, embeddings, RAG — and when not to
  • File types: YAML, Markdown, JSON, JSONL, and HTML for humans
  • Writing skills: writing for agents, against writing for humans

W06 Grill → spec

  • Cheap probes early beat large builds — measured
  • Why specs, not prompts
  • Being interviewed: the inversion
  • What a spec must contain: goals, non-goals, anti-goals
  • The boundary, and the success criteria
  • Qualifying a ground: the six criteria
  • Criterion 6 is the one that fails, and it fails late
  • IP and data governance: what you may paste into a model

W07 Tests

Opens with the Success and Failure gallery for P3 — AGENTS.md, domain GLOSSARY.md, one skill, docs/spec.md, ground qualified against the six criteria — which fell due the week before.

  • TDD as agent control infrastructure, not as a testing virtue
  • Unit, functional, eval: what each can and cannot catch
  • Spec-derived tests: from success criteria to assertions
  • Software architecture: deep modules
  • Deep modules for agent navigability, not for human comprehension
  • Tests and CI; GitHub Actions
  • Provenance: how do you know this number was computed and not generated?

W08 Tools

  • MCP as a protocol
  • MCP, against wrapping a solver
  • The API: the callable surface your ground exposes
  • Structured output and schemas as a reliability tool
  • YAML- and JSON-driven simulators
  • Screen control as a last resort
  • Hallucinated packages and APIs
  • Live case study: one discipline, one real tool

W09 Human in the loop

Opens with the Success and Failure gallery for P4 — Spec-derived tests green in CI; your MCP server, with the agent calling it — which fell due the week before.

  • Interactions with agents; drift; inflection
  • Intervention points as a declared, committed artifact
  • Observability: structured logging
  • JSONL runs: what to log, and why
  • Diagnosing from the log alone
  • Inflection points: the ledger of what actually moved the work
  • Input yield: which of your interventions earn their cost — and naming the agent's failures
  • When not to use an agent: cost, latency, liability
  • Token economics, and the cost of context

W10 Verification

  • V&V: did we build the right thing? Did we build the thing right?
  • Eval suites: does my loop reliably converge?
  • Calibration: reliability diagrams
  • The Brier score
  • The coverage–accuracy tradeoff
  • Physical sanity checks: units, dimensional analysis, orders of magnitude
  • Red teaming

W11 System One decision models

Opens with the Success and Failure gallery for P5 — Intervention points declared, JSONL logging, one induced failure diagnosed from the log alone, first eval run — which fell due the week before.

  • System One decision models: not every decision in your loop needs a frontier LLM
  • Routing: which of your loop's repeated decisions are System One shaped
  • A category one semester old — its newness is the first teaching point, not a disclaimer
  • Where a confidence number comes from: a derived distribution, against a model sampling the tokens “90% confident” like any other tokens
  • “Calibrated” as a product claim almost nobody measures — week 10's instruments turned on a live field
  • One vendor concedes its own benchmarks “may be biased”; one competitor gated its claims properly, reported p = 0.065 as unresolved rather than as a win, and then shut down
  • Open-weights options, their licences, and what actually runs on a student machine
